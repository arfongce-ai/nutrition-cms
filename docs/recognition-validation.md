# 음식 인식과 분량 검증

현재 UI 테스트와 산술 테스트는 앱 동작을 검증합니다. 실제 음식 인식률이나 칼로리 정확도를 입증한 결과는 아직 없습니다. 앱은 모델 확신 점수나 DB 일치 여부를 정확도 백분율로 표시하지 않습니다.

## 실측 평가 자료 만들기

시작용으로 다양한 한식·반찬·포장식품 사진 100~200건을 모읍니다. 실제 먹는 부분을 저울로 재고, 같은 조리 상태의 영양표 또는 재료별 레시피 계산으로 기준 칼로리를 기록합니다. 레시피 계산도 기준값의 추정이라는 한계가 있으므로 사용한 출처와 계산 방법을 남깁니다. 사진만 보고 정한 무게를 기준값으로 사용하지 않습니다.

같은 식사를 연속 촬영한 사진은 하나의 묶음으로 관리합니다. 수정·개발에 사용한 식사와 최종 평가 식사를 분리하고, 사진 밝기·기기·음식 종류별로 평가합니다. 사진은 동의받아 수집하고, 평가 파일은 `.qa/` 등 Git에서 제외된 위치에 보관합니다. 앱이나 이 스크립트는 자료를 자동 업로드하지 않습니다.

JSON 배열의 각 항목에는 다음 필드를 넣습니다.

| 필드 | 내용 |
|---|---|
| id | 중복 없는 식사 ID |
| split | `test` (개발에 쓰지 않은 자료) |
| group | 한식 여러 반찬, 포장식품, 어두운 사진 등 평가 그룹 |
| referenceMethod | 저울 측정 방법, 영양표/레시피 출처와 날짜 |
| reference | 실제 음식의 `{name, grams, calories}` 배열 |
| predicted | 앱이 낸 `{name, grams, calories}` 배열. 미확인 수치는 null |

`node scripts/evaluate-meal-accuracy.mjs .qa/measured-meals.json`

음식 정밀도·재현율, 빠진 음식 수, 추가/오인식 수, 이름이 일치한 음식의 중량 평균 절대오차, 식사 전체 칼로리 평균 절대오차와 90백분위 오차를 출력합니다. 예측이 없는 식사도 전체 건수와 재현율·계산 가능 비율에 포함합니다. 상대오차는 기준 칼로리가 0인 식사를 제외하며 비교 건수를 함께 제공합니다. `calorieCoverage`가 낮다면 오차 평균만으로 모델을 비교하지 않습니다.

자동 이름 비교는 띄어쓰기와 계란/달걀 표기 차이만 정리합니다. 서로 다른 음식·조리법을 동의어로 등록하지 마세요. 필요하면 정답을 보지 않고 고정한 명칭 사전을 평가 전에 정합니다.

## 적용한 확인 흐름

- 사진 후보와 유사한 검색 결과는 구분합니다. 이름이 정확히 맞지 않는 후보는 사용자가 선택합니다.
- 먹은 양을 고르기 전에는 다음 단계나 저장으로 넘어가지 않습니다.
- 공기·개수는 표준 무게를 사용한 추정이며, 저울 입력·숫자 입력·표시 분량 선택을 별도로 저장합니다.
- DB 출처가 있다고 음식명과 중량까지 검증된 것으로 표시하지 않습니다.
- 모르는 영양값은 확인 필요로 표시하고 합계에서 빠졌음을 알립니다. 표시된 0은 미확인 값과 구분합니다.
- 실제 정확도 목표나 오차 범위는 실측 평가 후 정합니다.
