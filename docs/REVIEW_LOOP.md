# REVIEW_LOOP.md — Codex ↔ Claude Code 교차 리뷰

한쪽이 구현하면 다른 쪽이 리뷰·디버깅·보완한다. 도구 전환은 사용자가 한다. 동시 실행 금지.

## 0. 자동 게이트 (사람이 안 돌려도 됨)
푸시할 때마다 GitHub Actions(`.github/workflows/ci.yml`)가 테스트·빌드를 자동 실행한다.
- 리뷰어는 사람이 직접 돌리기 전에 GitHub 저장소의 Actions 탭에서 최신 커밋 배지(✅/❌)부터 확인한다.
- ❌면 원인을 먼저 고치고, 그 다음에 아래 1번부터 수동 리뷰를 진행한다.
- CI는 "새 실패 0"만 확인해줄 뿐 로직 오류·설계 문제는 못 잡는다 — 수동 리뷰(체크리스트)는 그대로 필요하다.

## 한 라운드
1. 작성자: 구현 → 테스트/빌드 → 커밋 → HANDOFF 로그 작성 (변경 파일, 테스트 결과, 의심되는 곳)
2. 리뷰어: 아래 순서로 진행
   - `git log -3`, `git diff <이전 커밋>..HEAD`로 변경 확인
   - 테스트/빌드를 직접 실행 (작성자의 결과를 믿지 않는다)
   - 체크리스트로 점검
   - 발견 목록을 먼저 HANDOFF에 기록 (수정 전)
   - 치명·중요 항목을 수정하고 항목당 작은 커밋으로 남긴다
   - 다시 테스트/빌드 후 로그에 결과 기록
3. 작성자: 리뷰어의 커밋과 로그를 확인하고 이의가 있으면 로그에 남긴다.
4. 다음 작업이면 역할을 바꾼다 (작성자 ↔ 리뷰어).

## 종료 조건
- 새로 생긴 테스트 실패 0, 빌드 성공
- 발견 항목 전부 "수정됨" 또는 "보류(사유)"
- 라운드는 작업당 최대 2회. 그 이상 의견이 갈리면 사용자가 결정한다.

## 발견 목록 형식 (HANDOFF 로그에 붙임)
| 심각도 | 파일:줄 | 문제와 근거 | 조치 |
|--------|---------|-------------|------|
| 치명/중요/경미 | path:123 | 재현 방법 또는 코드 근거 | 수정됨(커밋 해시) / 보류(사유) / 확인 필요 |

- 확신이 없으면 "확인 필요"로 적고 추측으로 고치지 않는다.
- 작성자의 설계 의도를 바꾸는 수정은 사용자 확인 후 진행한다.

## 이 프로젝트 체크리스트

데이터/API
- Firestore 문서에 저장하는 필드명과 읽는 쪽 필드명이 같은가 (과거 feedbackId, reply/memberReply 불일치로 읽음/답변이 실패한 적 있음)
- API 요청/응답 필드가 서버와 클라이언트에서 일치하는가
- docToPlain 등 변환 함수가 id와 필드를 어떻게 반환하는지 확인했는가

연동/보안
- CORS: 두 앱이 다른 Cloudflare Pages 오리진. _middleware.js, _shared/cors.js 적용 여부
- VITE_REQUIRE_MEMBER_LINK가 꺼진 상태에서 기존 동작이 그대로인가
- 연결코드 만료(10분), 재사용, 해제 후 접근 차단
- CMS로 나가는 필드가 가명 memberId + 영양 수치뿐인가 (이름/전화/주소/결제/원본 사진 없음)
- 비밀값이 코드/문서/로그에 없는가
- firestore.rules가 새 컬렉션을 막고 있는가

프론트엔드
- 실제 앱의 CSS 클래스 체계(라이트 테마 meal-*)를 쓰는가. 없는 토큰이나 클래스를 쓰지 않았는가
- App.jsx 삽입 지점 외 다른 부분을 건드리지 않았는가
- 로딩, 빈 상태, 오류 상태가 처리되는가

테스트
- momgagym-cms2: npm test 기준선 3059/3070 (기존 실패 11개는 무관, 새 실패만 본다)
- nutrition-cms: npm test 33/33, npm run build 성공
- CMS: wrangler functions build
- 새 기능에 테스트가 추가됐는가
- 테스트를 못 돌린 항목은 이유를 로그에 적는다 (예: Playwright 미설치)
